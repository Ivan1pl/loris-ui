# Development Roadmap

This roadmap lists the planned work for LorisUI. Priorities follow the maintainer's goals: use LorisUI in their own games, stabilise the API, publish it as a reusable library, and support more backends. It is a solo project, so the phases are ordered by dependency rather than by date.

## Current State (2026-10-12)
- **Version**: `1.0-SNAPSHOT` (publishable to the local Maven repository only)
- **Modules**: `api` (`lorisui.api`), `imgui` (`lorisui.imgui`), the internal MIT-only renderer ports `imgui-gles3` (`lorisui.imgui.gles3`) and `imgui-vulkan` (`lorisui.imgui.vulkan`), `jme3` (automatic module `lorisui.jme3`), `lwjgl` (`lorisui.lwjgl`), `examples`
- **Components**: Panel, Button, Text, Image, TextInput, NumberInput, ComboBox, ProgressBar, TabbedPanel, Popup, ModalPopup, Spacer
- **Recent work**: extracted into a standalone library and refactored into `backend/`, `renderer/impl/` and `renderer/style/impl/` packages; Java 25 toolchain, unit tests, the `LorisScreen` threading fix and the unified null-handling convention; then a toolkit-neutral `Backend` port (`render` only), JPMS module renames, dependency-scope cleanup, the jME screen lifecycle, and user-facing Javadoc for the whole exported API; then a Checkstyle build gate with `.editorconfig`, a renderer that owns its Dear ImGui context with teardown and re-attach, stable font handles registered on the renderer, a per-backend texture cache with unload, the registration API for renderers and style appliers, the host-neutral `ScreenManager` (with the hook re-entrancy guard and two-phase deactivation), `DeferredRelease` and `ResourceBundleKeyResolver`, unsigned glyph ranges, re-attachable jME displays, and the LWJGL/SDL3 host with its example (pre-1.0 breaking API changes); then local Maven publishing with sources and Javadoc jars and a Javadoc gate, jMonkeyEngine as a `compileOnly` dependency of `jme3`, the jME host sized in logical window coordinates, and the documented screen-size contract; then the GLFW + OpenGL 3 and SDL3 + SDL_GPU platform/renderer variants: the sealed `ImGuiRenderer` with its first three final variants, `long` texture IDs, the `ImGuiSdlGpuBackend` (sRGB GPU textures), backend-tiled Repeat images, the GLFW + OpenGL 3 and SDL_GPU LWJGL displays next to the SDL3 + OpenGL 3 one, and one example per display; the SDL3 + OpenGL 3 renderer, display, example and run task were renamed to `ImGuiSdlGl3Renderer`, `ImGuiLwjglSdlGl3Display`, `LorisLwjglSdlGl3Example` and `runLwjglSdlGl3Example` (pre-1.0 breaking renames, no shims); then the jME ANGLE/GLES3 and SDL3 + Vulkan variants: `ImGuiSdlGles3Renderer` with `ImGuiOpenGlEsBackend` and an OpenGL ES 3.0 port of `ImGuiImplGl3`, the jME display choosing GL3 or GLES3 from jME's renderer (so it works with jME 3.10's default `ANGLE_GLES3`), both GL backends restoring the texture binding and unpack state they change, `ImGuiSdlVulkanRenderer` with `ImGuiVulkanBackend` and a Vulkan 1.3 dynamic-rendering port of Dear ImGui's `imgui_impl_vulkan`, the fourth LWJGL display `ImGuiLwjglSdlVulkanDisplay` (in-frame close skips the frame's draws), the ported (MIT-licensed) code moved into the MIT-only subprojects `loris-ui-imgui-gles3` and `loris-ui-imgui-vulkan` (own `LICENSE` and single MIT POM license, packages exported only to `lorisui.imgui`), and one license per artifact (`META-INF/LICENSE` and the POM license from a per-project `ext.license`, Apache-2.0 by default), and the `LorisJme3Gl3Example` and `LorisLwjglSdlVulkanExample` examples (six run tasks); then press identity for buttons (a button clicks only when the press and the release land on it, tracked by ImGui ID in the per-backend `ButtonInputTracker`, resolving the `PanelRenderer` TODO), `Button.hoverAction` with `Button.hover()` (runs once each time the pointer starts hovering an enabled button; `ExampleScreen` counts hovers), and `:examples:runAllExamples` (all six examples at once, each in its own JVM) with the six run tasks registered from one shared example list
- **Gaps**: no README, no CI, no remote publishing (artifacts go only to the local Maven repository). Unit tests exist for `api`, `imgui`, `imgui-vulkan`, `lwjgl` and `jme3` (JUnit 6, Mockito in `api`; `jme3` has the `ImGuiJmeGraphicsApi` seam test), but not for `imgui-gles3` or `examples`; the native lifecycle (context, Impl objects, fonts, GL, GLES, GPU and Vulkan textures, GLFW callback chaining, re-attach) is verified only manually by running the examples. The GLES draw path under ANGLE and the whole Vulkan path (pipeline, uploads, synchronization, swapchain recreation, MoltenVK, the in-frame close) are manual-only, and the Vulkan classes' unit tests cover only their argument checks
- **Breaking changes (pre-1.0, no shims)** from the button press identity work:
  - A button clicks only when the press and the release both land on it: a press that starts elsewhere (another button, empty space, a text field) no longer clicks the button under the release, nor does the click that closes a popup or the ComboBox dropdown
  - An `ImGuiBackend` must not be shared between renderers or Dear ImGui contexts: its `PanelRenderer` keeps button press and hover state across frames, so a shared backend loses clicks
- **Breaking changes (pre-1.0, no shims)** from the jME ANGLE/GLES3 and SDL3 + Vulkan variants work:
  - `ImGuiRenderer` permits two more variants (`ImGuiSdlGles3Renderer`, `ImGuiSdlVulkanRenderer`), so exhaustive `switch` statements over `ImGuiRenderer` in client code no longer compile
  - `runJme3Example` (and `LorisJme3Example`) now runs with jME's default `ANGLE_GLES3` renderer; the OpenGL 3.3 run is `runJme3Gl3Example`
  - `ImGuiJmeDisplay`'s constructor throws `IllegalStateException` for jME renderers other than `ANGLE_GLES3` and `LWJGL_OPENGL*`
  - `ImGuiOpenGlBackend` now restores the texture binding and unpack state it changes when it loads a texture
  - `lorisui.imgui` and `lorisui.lwjgl` declare a plain `requires static org.lwjgl.vulkan` (and `lorisui.imgui` `requires static org.lwjgl.opengles`): a modular application that uses the Vulkan variant must `requires org.lwjgl.vulkan` itself
  - `loris-ui-imgui` has two new runtime dependencies, `loris-ui-imgui-gles3` and `loris-ui-imgui-vulkan` (MIT), which `lorisui.imgui` requires, so on the module path both must be present for every host; applications never require them
- **Breaking changes (pre-1.0, no shims)** from the platform/renderer variants work:
  - The SDL3 + OpenGL 3 classes and task are renamed: the renderer is now `ImGuiSdlGl3Renderer` (with the sealed base `ImGuiRenderer`), the LWJGL display `ImGuiLwjglSdlGl3Display`, the example `LorisLwjglSdlGl3Example` and its run task `runLwjglSdlGl3Example`
  - Texture IDs are `long`: `TextureData.id` and the `id` parameter of `RendererProvider.renderTexture`
  - OpenGL textures use `GL_CLAMP_TO_EDGE` (also in the jME host); Repeat images are tiled by the backend instead of `GL_REPEAT`, so a custom renderer that draws a texture with UVs above 1 no longer repeats it
  - `lorisui.imgui` now `requires org.lwjgl.sdl`, so the LWJGL SDL3 binding (supplied by imgui-java) must be on the module path at runtime for every host

## Phase 2: API Stabilisation
- [x] **Unit tests for pure logic** — `ImageMode` construction, `Color` packing and `mask`, builder defaults, `LorisScreen` layout handoff, `ImGuiBackend` renderer and style-applier lookup (superclass fallback, missing-renderer error), texture-cache keying and masking, class-path resource lookup `[Effort: M]`
- [x] **`LorisScreen` threading fix** `[Effort: S]`
  - [x] Thread-safe `content` handoff (`volatile` content, atomic update flag)
  - [x] Exceptions from `layout()` (and a `null` result) surface once as `IllegalStateException` from `render()`
  - [x] Layout executor runs on a daemon thread (`lorisui-layout`), so it doesn't keep the JVM alive
  - [x] Layout work can be stopped: `LorisScreen.shutdownLayoutUpdates()` (called by both hosts on teardown) shuts the worker down, and the next requested layout starts it again
- [x] **Texture lifecycle** — the texture cache is per `ImGuiBackend` instance with keys normalized to class-path style (`"/x.png"` and `"x.png"` share one texture); renderers reach it through `RendererProvider.loadTexture`/`renderTexture`; `unloadTextures()` deletes every texture (`ImGuiOpenGlBackend.deleteTexture` and `ImGuiOpenGlEsBackend.deleteTexture` free the GL name, `ImGuiSdlGpuBackend.deleteTexture` releases the GPU texture, `ImGuiVulkanBackend.deleteTexture` waits for the queue and destroys the Vulkan objects) and runs automatically on renderer teardown. Per-path eviction was left out `[Effort: M]`
- [x] **Null-handling convention** — applied across components and styles (see `standards/java/error-handling.md`): optional `Supplier` properties default to `() -> null`, `Supplier` setters and required arguments use `Objects.requireNonNull`, constant overloads of optional properties accept `null` as unset `[Effort: S]`
- [x] **Javadoc** — user-facing Javadoc for every exported package of `lorisui.api`, `lorisui.imgui` and `lorisui.lwjgl` and for `jme3`, with `package-info.java` per package and module doc comments, including runtime notes (`--enable-native-access`, macOS `-XstartOnFirstThread` for the LWJGL host, Dear ImGui assertions ending the JVM, global SDL hints, font memory); strict doclint (`-Xdoclint:all`) reports zero warnings `[Effort: M]`
- [x] **JPMS cleanup** — modules named `lorisui.api` / `lorisui.imgui` (`requires transitive lorisui.api`); `jme3` is an automatic module (`Automatic-Module-Name: lorisui.jme3`) with no compiler workarounds `[Effort: M]`
- [ ] **jme3 `module-info`** — blocked while jME3 jars split packages `[Effort: S]`
- [x] **jME screen lifecycle** — screen registration, switching and localization-key validation, matched `onStartScreen`/`onEndScreen` hooks with exception-safe switches (now in the host-neutral `ScreenManager`), and the example removes the display in `destroy()` (jME doesn't call `cleanup` on exit) `[Effort: S]`
- [x] **Renderer teardown and re-attach** — `ImGuiRenderer` owns its context: `initialize()` creates the context and fresh Impl objects of its variant (for example `ImGuiImplSdl3`/`ImGuiImplGl3` in `ImGuiSdlGl3Renderer`) and replays the registered fonts; `dispose()` releases textures, the renderer and platform Impl objects and the context. Neither runs inside a frame, and both hosts defer teardown requested mid-frame or from a hook. A removed jME display can be attached again; Dear ImGui UI state resets on re-attach `[Effort: M]`
- [x] **Re-entrancy guard for `setCurrentScreen`** — `ScreenManager` rejects `setCurrentScreen`, `activate()` and `deactivate()` from inside a screen hook with `IllegalStateException` before changing state `[Effort: S]`
- [x] **Shared deferred teardown** — the host-neutral `DeferredRelease` (`run`/`request`/`isPending`, `runAll`, `runAfterFailure`) replaces the helpers each host and the renderer carried, and `ScreenManager.beginDeactivation()` makes screen switches during a pending teardown only record the choice; both are unit-tested `[Effort: S]`
- [x] **Glyph ranges above U+7FFF** — font glyph ranges are built as unsigned 16-bit code points, so CJK ranges load, and malformed ranges fail at registration with `IllegalArgumentException`; a font Dear ImGui cannot load fails `initialize()` with `IllegalStateException` naming its source, and font data of 100 bytes or less (a JVM-ending Dear ImGui assertion) fails registration with `IOException` `[Effort: S]`
- [x] **jME HiDPI size** — the jME host passes the window size from `SDL_GetWindowSize` (logical window coordinates) each frame, like the LWJGL host, so the UI is sized correctly on HiDPI displays and follows resizes; jME's emulated display-scale modes (above 1) are documented as unsupported; manual check on a display with scale > 1 pending `[Effort: S]`
- [ ] **Fail once for missing images** — a missing or unreadable image fails the screen's render on every draw; cache the failure or report it once `[Effort: S]`
- [ ] **Bundle-name validation (optional)** — reject resource-bundle names containing `.` in `setResourceBundle`, since keys split at the first dot can't resolve them `[Effort: S]`
- [ ] **Popup open-flag protocol (B2)** — redesign how a popup's open state is bound. A `Popup` nested inside a panel uses the inherited `open(Supplier)` binding (default `false`), so it never shows after `open()` unless `open(() -> true)` is also set `[Effort: M]`
- [ ] **Optional or automatic panel IDs (B3)** — panel IDs are required stable keys that must be unique among siblings `[Effort: S]`
- [ ] **Input validation gaps** — `NumberInput.validateInput(null)` is silently ignored while `TextInput` throws `NullPointerException`; min/max/maxLength suppliers that return `null`, or a negative maxLength, fail late (when the value is committed); a `null` `ComboBox.Item.item` fails at draw time `[Effort: S]`
- [ ] **ComboBox default size** — a `ComboBox` built with neither `size` nor a sized empty-selection label comes out 0×0 `[Effort: S]`
- [x] **Content-function size arguments** — decided: content functions (`IntBiFunction`), like size bindings, receive the screen width and height, not the parent panel's size, at every nesting level, and position bindings receive it for top-level panels and popups (a nested panel is placed by its parent's layout); the contract and the unit (logical window pixels) are documented in the `api` Javadoc `[Effort: S]`

## Phase 4: Additional Backends & Hosts
- [x] **Validate the backend abstraction** — `Backend` declares only `render`; texture loading and drawing live in `ImGuiBackend`, and hosts read input capture through `ImGuiRenderer` instead of ImGui `[Effort: M]`
- [x] **Renderer/style-applier registration API** — `registerRenderer`/`registerStyleApplier` on `ImGuiBackend` (replacing existing mappings; `getRenderer`/`getStyleApplier` are final) and on every display (jME and the four LWJGL displays) before initialization `[Effort: S]`
- [x] ~~**Custom backend in the jME host**~~ — superseded by display-level registration: custom components work in the jME host without a custom backend `[Effort: S]`
- [ ] **Neutral host SPI** — a toolkit-neutral host contract (`UiRuntime`) covering frame begin/end and input capture `[Effort: M]`
- [ ] **Neutral `Font` abstraction (B4)** — `Font` instances come from a specific backend and work only with it `[Effort: M]`
- [ ] **Toolkit-neutral style vocabulary (B6)** — style properties are passed to the backend as given and may be ignored by backends that lack the feature `[Effort: M]`
- [x] **Second host integration** — `loris-ui-lwjgl` (`ImGuiLwjglSdlGl3Display`) embeds LorisUI in an application's own LWJGL SDL3 window and loop, reusing the `imgui` module; `LorisLwjglSdlGl3Example` renders the shared `ExampleScreen` `[Effort: L]`
- [x] **Platform/renderer variants: GLFW+GL3 and SDL3+SDL_GPU (renderers, GPU texture backend, LWJGL displays, examples)** — the sealed `ImGuiRenderer` with `ImGuiSdlGl3Renderer`, `ImGuiGlfwGl3Renderer` and `ImGuiSdlGpuRenderer`; `ImGuiSdlGpuBackend` with sRGB GPU textures; Repeat tiled by the backend instead of `GL_REPEAT`; `ImGuiLwjglGlfwGl3Display` (chained GLFW callbacks) and `ImGuiLwjglSdlGpuDisplay` (application-owned command buffer and target) next to `ImGuiLwjglSdlGl3Display`; one example per display, all rendering `ExampleScreen`; checked manually `[Effort: L]`
- [x] **jME ANGLE/GLES3 and SDL3 + Vulkan variants** — `ImGuiSdlGles3Renderer` + `ImGuiOpenGlEsBackend` (an OpenGL ES 3.0 port of `ImGuiImplGl3`, `GL_SRGB8_ALPHA8` textures), selected by `ImGuiJmeDisplay` for jME's default `ANGLE_GLES3` renderer through the unit-tested `ImGuiJmeGraphicsApi` seam (GL3 for `LWJGL_OPENGL*`, `IllegalStateException` otherwise); GL texture loads restore the texture binding and unpack state; `ImGuiSdlVulkanRenderer` + `ImGuiVulkanBackend` (a Vulkan 1.3 dynamic-rendering port of `imgui_impl_vulkan`, `R8G8B8A8_SRGB` textures uploaded synchronously, `skipFrameDraw()` for in-frame teardown) with `ImGuiLwjglSdlVulkanDisplay`; the ported code in the MIT-only subprojects `loris-ui-imgui-gles3` and `loris-ui-imgui-vulkan` (each with its own `LICENSE` and a single MIT POM license), every other artifact Apache-2.0 only; `LorisJme3Example` on ANGLE, `LorisJme3Gl3Example` and `LorisLwjglSdlVulkanExample`; native paths checked manually `[Effort: L]`
- [ ] **Second rendering backend** — a non-ImGui implementation of `Backend` that proves `api` is fully toolkit-agnostic `[Effort: L]`
